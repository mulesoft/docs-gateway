//tag::secure-password-intro[]
[[redis-password]]
== Secure the Redis Password

To avoid storing the Redis `password` in plaintext in the YAML configuration file, store it in your deployment environment's secret store and inject it into the shared storage configuration when the Flex Gateway container starts.

Omni Gateway reads shared storage configuration only from a file in the `conf.d` directory. You can't reference an external secret directly from the `sharedStorage` configuration. These examples generate the configuration file from the stored secret at container startup, so you don't store the password in plaintext on disk.

//end::secure-password-intro[]
//tag::secure-password-k8s[]
=== Secure the Redis Password in Kubernetes

. Store the Redis password in a Kubernetes Secret:
+
[source,ssh]
----
kubectl create secret generic redis-password --from-literal=password='<your-redis-password>'
----
+
Replace `<your-redis-password>` with your Redis password.

. In your Flex Gateway `Deployment`, mount the secret as a file and override the container command to read the password, write the shared storage configuration to a directory that Flex Gateway scans, and then start Flex Gateway. For example:
+
[source,yaml]
----
apiVersion: apps/v1
kind: Deployment
metadata:
  name: flex-gateway
spec:
  replicas: 1
  selector:
    matchLabels:
      app: flex-gateway
  template:
    metadata:
      labels:
        app: flex-gateway
    spec:
      containers:
      - name: flex-gateway
        image: mulesoft/flex-gateway:latest
        command: ["/bin/sh", "-c"]
        args:
        - |
          REDIS_PASSWORD=$(cat /etc/redis-secret/password)
          cat <<EOF > /etc/mulesoft/flex-gateway/conf.d/shared-storage-config.yaml
          apiVersion: gateway.mulesoft.com/v1alpha1
          kind: Configuration
          metadata:
            name: shared-storage-redis
          spec:
            sharedStorage:
              redis:
                address: "<your-redis-host>:6379"
                password: "$REDIS_PASSWORD"
          EOF
          /init
        volumeMounts:
        - name: redis-password
          mountPath: /etc/redis-secret
          readOnly: true
        - name: shared-storage-config
          mountPath: /etc/mulesoft/flex-gateway/conf.d
      volumes:
      - name: redis-password
        secret:
          secretName: redis-password
      - name: shared-storage-config
        emptyDir: {}
----
+
In this configuration:
+
* The `redis-password` volume mounts the `redis-password` secret at `/etc/redis-secret` in the container.
* The container command reads the password from `/etc/redis-secret/password`, generates `shared-storage-config.yaml` in the `/etc/mulesoft/flex-gateway/conf.d` directory, and then starts Flex Gateway (`/init`).
* The `shared-storage-config` `emptyDir` volume provides a writable location for the generated configuration file. Because this directory is separate from the directory that stores your registration configuration, generating the file doesn't overwrite your registration.

//end::secure-password-k8s[]
//tag::secure-password-docker[]
=== Secure the Redis Password in Docker

. Create a file that contains the Redis password:
+
[source,ssh]
----
echo '<your-redis-password>' > /path/to/redis_password.txt
----
+
Manage this file with your secret store and restrict access to it.

. Start the Flex Gateway container with the password file mounted, and override the command to generate the shared storage configuration before starting Flex Gateway:
+
[source,ssh]
----
docker run --rm \
--name flex-gateway \
-v /path/to/redis_password.txt:/etc/redis-secret/password:ro \
-v "$(pwd)":/usr/local/share/mulesoft/flex-gateway/conf.d \
-p 8080:8080 \
--entrypoint /bin/sh \
mulesoft/flex-gateway -c '\
REDIS_PASSWORD=$(cat /etc/redis-secret/password); \
cat <<EOF > /etc/mulesoft/flex-gateway/conf.d/shared-storage-config.yaml
apiVersion: gateway.mulesoft.com/v1alpha1
kind: Configuration
metadata:
  name: shared-storage-redis
spec:
  sharedStorage:
    redis:
      address: "<your-redis-host>:6379"
      password: "$REDIS_PASSWORD"
EOF
/init'
----
+
This command mounts the password file read-only, writes `shared-storage-config.yaml` to the in-container `/etc/mulesoft/flex-gateway/conf.d` directory, and then starts Flex Gateway (`/init`). Because the generated file is written inside the container instead of to the mounted host directory, the password isn't stored in plaintext on the host.

//end::secure-password-docker[]

[[redis-tls]]
== Configure TLS for Redis-Based Shared Storage

Use TLS with Redis to ensure data security between Flex Gateway and the Redis instance. Configuring TLS enables you to protect sensitive data, prevent unauthorized access, and maintain the reliability of your services. Additionally, configuring TLS helps organizations meet compliance requirements and build trust with users.

TLS works with both Redis and Redis Sentinel.

Configure TLS for Redis-based shared storage using the steps described in the previous sections.

Sample configuration for adding Redis-based shared storage with TLS:
//end::tls-intro[]

//tag::tls-sample-config[]
[source, yaml]
----
apiVersion: gateway.mulesoft.com/v1alpha1
kind: Configuration
metadata:
  name: shared-storage-redis
spec:
  sharedStorage:
    redis:
      address: internal.redis.com:6379
      tls:
        skipValidation: false
        minVersion: "1.1"
        maxVersion: "1.3"
        alpn:
          - h2
          - http/1.1
        ciphers:
          - TLS_AES_128_GCM_SHA256
          - TLS_AES_256_GCM_SHA384
          - TLS_CHACHA20_POLY1305_SHA256
          - TLS_RSA_WITH_3DES_EDE_CBC_SHA
          - TLS_RSA_WITH_AES_128_CBC_SHA
          - TLS_RSA_WITH_AES_256_CBC_SHA
          - TLS_RSA_WITH_AES_128_CBC_SHA256
          - TLS_RSA_WITH_AES_128_GCM_SHA256
          - TLS_RSA_WITH_AES_256_GCM_SHA384
          - TLS_ECDHE_ECDSA_WITH_AES_128_CBC_SHA
          - TLS_ECDHE_ECDSA_WITH_AES_256_CBC_SHA
          - TLS_ECDHE_RSA_WITH_AES_128_CBC_SHA
          - TLS_ECDHE_RSA_WITH_AES_256_CBC_SHA
          - TLS_ECDHE_RSA_WITH_AES_128_GCM_SHA256
          - TLS_ECDHE_ECDSA_WITH_AES_128_GCM_SHA256
          - TLS_ECDHE_RSA_WITH_AES_256_GCM_SHA384
          - TLS_ECDHE_ECDSA_WITH_AES_256_GCM_SHA384
          - TLS_ECDHE_RSA_WITH_CHACHA20_POLY1305_SHA256
          - TLS_ECDHE_ECDSA_WITH_CHACHA20_POLY1305_SHA256
        trustedCA: |
          -----BEGIN CERTIFICATE-----
          ...
          -----END CERTIFICATE-----

        certificate:
          keyPassphrase: "****"
          key: |
            -----BEGIN RSA PRIVATE KEY-----
            ...
            -----END RSA PRIVATE KEY-----

          crt: |
            -----BEGIN CERTIFICATE-----
            ...
            -----END CERTIFICATE-----

----
