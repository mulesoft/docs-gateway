== Summary

The WebSocket Connection Limit policy tracks in-flight WebSocket upgrades for the API instance where you apply it. Flex Gateway evaluates only requests whose `Upgrade` header equals `websocket`, skips ordinary HTTP traffic, and stores the counter in shared data so every replica shares the same ceiling.

If an upgrade request arrives and Flex Gateway reserves capacity, Flex Gateway it increments the counter before forwarding the handshake upstream. If the upstream response isn't `101 Switching Protocols`, Flex Gateway immediately releases the reservation. When the WebSocket exchange completes, Flex Gateway decrements the counter.

When the counter already equals `maximumConnections`, Flex Gateway stops the handshake and returns `429 Too Many Requests` with the plain text payload `Too many WebSocket connections`.

Set `maximumConnections` to an integer of `1` or higher. Flex Gateway rejects configuration that sets the value to `0` or omits the field.

Apply this policy at the **API** scope on Flex Gateway API instances that expose WebSocket interfaces.

== Configuring Policy Parameters

include::partial$policy-title-headers.adoc[tag=configFile]

----
- policyRef:
    name: websocket-connection-limit-flex
  config:
    maximumConnections: <integer> // REQUIRED, minimum 1
----

[%header%autowidth.spread,cols="a,a,a,a"]
|===

| Parameter | Required or Optional | Default Value | Description

| `maximumConnections`
| Required
| In Anypoint Platform, the UI defaults to `100`. If you use declarative YAML, you must supply an integer.
| Maximum number of simultaneous WebSocket upgrade reservations that Flex Gateway allows for this policy instance.

|===

==== Resource Configuration Example

[source,yaml]
----
- policyRef:
    name: websocket-connection-limit-flex
  config:
    maximumConnections: 500
----
