== Summary

The WebSocket Connection Limit policy tracks the number of active WebSocket connections for a specific API instance. Flex Gateway identifies these requests by the `Upgrade: websocket` header and ignores standard HTTP traffic. To ensure accuracy across distributed environments, Flex Gateway stores the connection counter in shared data so that all gateway replicas enforce a single, unified limit.

When a WebSocket upgrade request arrives, Flex Gateway increments the counter to reserve capacity before forwarding the handshake to the upstream service. If the upstream service doesn't return a `101 Switching Protocols` response, Flex Gateway releases the reservation. After a successful WebSocket connection closes, Flex Gateway decrements the counter.

If the counter reaches the `maximumConnections` limit, Flex Gateway rejects the upgrade request and returns a 429 error with the plain-text message `Too many WebSocket connections`.


== Configuring Policy Parameters

include::partial$policy-title-headers.adoc[tag=configFile]

----
- policyRef:
    name: websocket-connection-limit-flex
  config:
    maximumConnections: <integer> // REQUIRED, minimum 1
----

[%header%autowidth.spread,cols="a,a,a,a"]
|===

| Parameter | Required | Default Value | Description

| `maximumConnections`
| Yes
| —
| The maximum number of simultaneous WebSocket connections allowed. The value must be an integer of 1 or greater.

|===

==== Resource Configuration Example

[source,yaml]
----
- policyRef:
    name: websocket-connection-limit-flex
  config:
    maximumConnections: 500
----

|===
s|Field s|Description s|Default s|Required

| Maximum Connections
| Maximum number of concurrent WebSocket connections allowed for the API instance.
| `100` | Yes

[NOTE]
====
The JSON schema in API Manager accepts `0` as the minimum value. However, Flex Gateway rejects `0` at runtime because the limit must be at least `1`.
====
