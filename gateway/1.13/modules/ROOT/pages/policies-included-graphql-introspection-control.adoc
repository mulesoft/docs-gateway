== Summary

GraphQL servers expose built-in introspection meta-fields. Clients use them to discover types and fields. The GraphQL Introspection Control policy inspects each incoming GraphQL operation and blocks requests that reference meta-fields you configure to block:

* `__schema`, used for full schema discovery
* `__type`, used to look up a type by name
* `__typename`, used to read the concrete type name of an object

You choose independently whether to block each meta-field. By default, none are blocked, so all three meta-fields are allowed and the policy doesn't change traffic until you set one or more block flags to `true`.

After Flex Gateway resolves the GraphQL query, the policy evaluates the operation text. For persisted queries, the gateway resolves the document without the usual inline query text, so the policy doesn't inspect those requests, and they pass through without introspection checks.

If a request includes a meta-field you configured to block, the policy returns *403 Forbidden* with `Content-Type: application/json` and a JSON body that includes an `errors` array, such as `{"errors":[{"message":"Introspection field '__schema' is not allowed"}]}`.

Use this policy on Flex Gateway API instances that expose a GraphQL interface. Apply it at the API or resource scope as needed.

== Configuring Policy Parameters

include::partial$policy-title-headers.adoc[tag=configFile]

----
- policyRef:
    name: graphql-introspection-control-flex
  config:
    blockSchema: <boolean> // OPTIONAL, default: false
    blockType: <boolean> // OPTIONAL, default: false
    blockTypename: <boolean> // OPTIONAL, default: false
----

[%header%autowidth.spread,cols="a,a,a,a"]
|===

| Parameter | Required or Optional | Default Value | Description

| `blockSchema`
| Optional
| `false`
| When `true`, the policy returns 403 when the operation references the `__schema` meta-field anywhere in the document.

| `blockType`
| Optional
| `false`
| When `true`, the policy returns 403 when the operation references the `__type` meta-field.

| `blockTypename`
| Optional
| `false`
| When `true`, the policy returns 403 when the operation references the `__typename` meta-field.

|===

==== Resource Configuration Example

The following example blocks schema and type introspection while still letting clients use `__typename` where they need it:

[source,yaml]
----
- policyRef:
    name: graphql-introspection-control-flex
  config:
    blockSchema: true
    blockType: true
    blockTypename: false
----

|===
s|Field s|Description s|Default Value s|Required or Optional

| Block `__schema`

| Disabled, schema introspection allowed | Optional

| Block `__type`
| When enabled, clients can't use the `__type` meta-field to query details about a specific type by name.
| Disabled, type introspection allowed | Optional

| Block `__typename`
| When enabled, clients can't use the `__typename` meta-field to read the concrete type name of an object.
| Disabled, `__typename` allowed | Optional

| Advanced options
| Standard policy options such as policy version and application rules.
| |
|===

[NOTE]
====
In Anypoint Platform, *Block* toggles map directly to the declarative flags. When you enable *Block `__schema`*, Anypoint Platform sets `blockSchema` to `true` in the policy configuration that Flex Gateway receives.
====
