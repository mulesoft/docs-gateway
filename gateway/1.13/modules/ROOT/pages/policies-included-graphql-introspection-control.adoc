== Summary

GraphQL servers include built-in introspection fields that allow clients to discover your API's types and structure. Configure The GraphQL Introspection Control policy inspects incoming operations blocks requests that reference restricted fields.

Use the introspection policy to block requests a combination of these fields:

* `__schema`, used to discover the full API schema.
* `__type`, used to look up details for a specific type by name.
* `__typename`, used to read the concrete type name of an object.

Blocking `__typename` can affect GraphQL client libraries that rely on it for result caching.

* `__schema`, used to discover the full API schema.
* `__type`, used to look up details for a specific type by name.
* `__typename`, used to read the concrete type name of an object.

Blocking `__typename` can affect GraphQL client libraries that rely on it for result caching.

You can block specific introspection fields independently. By default, Flex Gateway allows all three fields(`blockSchema`, `blockType`, and `blockTypename` each default to `false`). The policy affects traffic only if you set one or more fields to `true`.

After Flex Gateway resolves the GraphQL query, the policy evaluates the operation text. Because Flex Gateway doesn't inspect the operation text for persisted queries, these requests pass through without introspection checks.

== Configuring Policy Parameters

include::partial$policy-title-headers.adoc[tag=configFile]

----
- policyRef:
    name: graphql-introspection-control-flex
  config:
    blockSchema: <boolean> // OPTIONAL, default: false
    blockType: <boolean> // OPTIONAL, default: false
    blockTypename: <boolean> // OPTIONAL, default: false
----

[%header%autowidth.spread,cols="a,a,a,a"]
|===

| Parameter | Required | Default Value | Description

| `blockSchema`
| No
| `false`
| If `true`, Flex Gateway returns a 403 error when the operation references the `__schema` meta-field anywhere in the document.

| `blockType`
| No
| `false`
| If `true`, Flex Gateway returns a 403 error when the operation references the `__type` meta-field.

| `blockTypename`
| No
| `false`
| If `true`, Flex Gateway returns a 403 error when the operation references the `__typename` meta-field.

|===

==== Resource Configuration Example

This example blocks schema and type introspection, but clients can still use `__typename`:

[source,yaml]
----
- policyRef:
    name: graphql-introspection-control-flex
  config:
    blockSchema: true
    blockType: true
    blockTypename: false
----

|===
s|Field s|Description s|Default Value s|Required

| **Block** `__schema` (`blockSchema`)
| If `true`, Flex Gateway blocks queries that use the `__schema` field for full schema discovery.
| Disabled, schema introspection allowed | No

| **Block** `__type` (`blockType`)
| If `true`, Flex Gateway blocks queries that use the `__type` field to look up a type by name.
| Disabled, type introspection allowed | No

| **Block** `__typename` (`blockTypename`)
| If `true`, Flex Gateway blocks queries that use the `__typename` field to read an object's concrete type name.
| Disabled, `__typename` allowed | No
|===
