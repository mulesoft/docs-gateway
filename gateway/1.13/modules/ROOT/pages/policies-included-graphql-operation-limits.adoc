== Summary

The GraphQL Operation Limits policy limits incoming request document's depth, aliases, root fields, and directives. When the operation exceeds a limit, the policy returns a `400` error code and a json `errors` array containing the exceeded limits. You can limit any combination of these fields:


* Maximum depth: The deepest nesting of field selections in the document. For example, a query `{ hero }` has a depth of 1, and `{ hero { name } }` has a depth of 2.
* Maximum aliases: The total count of field aliases across the document including nested fields.
* Maximum root fields: The maximum number of top-level fields for any operation in the document. Selections inside inline fragments at the root add to this count.
* Maximum directives: The maximum number of directives across the document's operations, fragments, spreads, inline fragments, and fields.

Flex Gateway evaluates limits at parse time from the document text. Because fragment spreads don't expand, metrics reflect the written document instead of a fully expanded query plan that the gateway builds at runtime.

For persisted queries, the gateway resolves the document without inline query text. The policy bypasses these requests and allows them to pass to the upstream service.

If the parser can't read the query, the policy logs a debug message and doesn't block the request, so upstream validation or other policies can still run.



== Configuring Policy Parameters

include::partial$policy-title-headers.adoc[tag=configFile]

----
- policyRef:
    name: graphql-operation-limits-flex
  config:
    maxDepth: <integer> // OPTIONAL, use -1 or omit to disable
    maxAliases: <integer> // OPTIONAL, use -1 or omit to disable
    maxRootFields: <integer> // OPTIONAL, use -1 or omit to disable
    maxDirectives: <integer> // OPTIONAL, use -1 or omit to disable
----

[%header%autowidth.spread,cols="a,a,a,a"]
|===

| Parameter | Required | Description

| `maxDepth`
| Optional
| Omit or `-1` to disable
| Maximum depth of nested fields in a single document.

| `maxAliases`
| Optional
| Omit or `-1` to disable
| Maximum number of field aliases in the document.

| `maxRootFields`
| Optional
| Omit or `-1` to disable
| Maximum number of top-level fields that an operation can declare.

| `maxDirectives`
| Optional
| Omit or `-1` to disable
| Maximum number of directives across the document.

|===

==== Resource Configuration Example

This example caps depth and aliases while leaving root fields and directives unrestricted.

[source,yaml]
----
- policyRef:
    name: graphql-operation-limits-flex
  config:
    maxDepth: 8
    maxAliases: 20
    maxRootFields: -1
    maxDirectives: -1
----

include::partial$policy-title-headers.adoc[tag=ui]

[%header%autowidth.spread,cols="a,a,a"]
|===
|Field |Description ||Required

| Maximum Depth
| Maximum depth of nested fields in a single document.
| `-1`, limit off | Optional

| Maximum Aliases
| Maximum number of field aliases in the document. Set to -1 to disable this limit.
| `-1`, limit off | Optional

| Maximum Root Fields
| Maximum number of top-level fields that an operation can declare. Set to -1 to disable this limit.
| `-1`, limit off | Optional

| Maximum Directives
| Maximum number of directives across the document. Set to -1 to disable this limit.
| No

| Advanced options
| Standard policy options, such as policy version and application rules.
| |
|===

[NOTE]
====
To start the policy, supply at least `{}` in the declarative configuration. If you want to enforce limits, add integer fields.
