== Summary

The A2A PII Detector policy detects personally identifiable information (PII) in requests sent to the agent. The policy is request-side only and never inspects or rewrites responses. If PII is detected, you can either log or block the request. A policy violation is reported when PII is detected.

== Configuring Policy Parameters

The A2A PII Detector policy isn't supported in Local Mode.

include::partial$policy-title-headers.adoc[tag=ui]

[%header%autowidth.spread,cols="a,a,a"]

|===
| Element | Required | Description
| PII Types | Yes | Array of built-in PII types to detect. Supported values are *Email*, *US SSN*, *Credit Card*, and *Phone Number*. For more information, see <<pii-types>>.
| Custom PII Patterns | No | Array of custom regex patterns to detect additional sensitive values. Define a name and regex pattern for each array entry. For example, use `name: AWS Access Key` and `pattern: AKIA[0-9A-Z]{16}` to detect AWS access keys.
| Action | No | Action to take when PII is detected. Supported values are *Reject*, *Log*, and *Log and mask*. Default is *Log*.
|===

== How This Policy Works

The policy scans A2A v1 requests for PII. It only scans requests using the `SendMessage` and `SendStreamingMessage` methods. Within those requests, the policy recursively inspects all string values in `Part::Text` entries inside `params.message.parts[]`. Other request types, file parts (`Part::File`), and structured data parts (`Part::Data`) are never scanned.

For request processing:

* If *Action* is *Reject*, the policy blocks the request and returns a JSON-RPC 2.0 error response.
* If *Action* is *Log*, the policy forwards the request and logs findings with actual PII values.
* If *Action* is *Log and mask*, the policy forwards the request and logs findings with masked values.

The policy detects overlapping PII patterns and keeps the longest (most specific) match. For example, a credit card number with delimiters that could also match an SSN pattern is detected as a credit card.

== PII Types

When you configure the A2A PII Detector policy, choose which types of PII to detect.

[%header,cols='1a,5a']
|===
|PII Type
|Description

|Email
|Standard email addresses such as `User.Name+tag@example.com`.

|US SSN
|United States Social Security Numbers (SSNs), including formats with various delimiters such as `123-45-6789`, `123 45 6789`, `123.45.6789`, `123,45,6789`, `123/45/6789`, `123\45\6789`, or `123456789`.

|Credit Card
|Credit card numbers for Visa, MasterCard, American Express, and Discover, with or without separators. Examples: `4111-1111-1111-1111`, `4111 1111 1111 1111`, `4111111111111111`, `4111.1111.1111.1111`, `5500-0000-0000-0004`, `3782-822463-10005`, `6011-0000-0000-0004`.

|Phone Number
|Phone numbers in common domestic and international formats based on ITU E.164 country codes. Examples include US numbers like `(555) 123-4567`, `555-123-4567`, `+1-555-123-4567`, and international numbers like `+91 98765 43210`, `+44 20 7946 0958`, `+49 30 12345678`.
|===

== Response on Reject

When the policy blocks a request, it returns an HTTP 403 status with a JSON-RPC 2.0 error response:

[source,json]
----
{
  "jsonrpc": "2.0",
  "id": null,
  "error": {
    "code": -32600,
    "message": "Request contains PII data: SSN: 123-45-6789",
    "data": [
      {
        "@type": "type.googleapis.com/google.rpc.ErrorInfo",
        "domain": "a2a-protocol.org",
        "reason": "FORBIDDEN",
        "metadata": { "detail": "Request contains PII data: SSN: 123-45-6789" }
      }
    ]
  }
}
----

== Example Request and Logging

This example shows a request containing multiple PII types and the corresponding log output for different action configurations:

[source,json]
----
{
  "jsonrpc": "2.0",
  "method": "message/send",
  "params": {
    "text": "Contact me at john.doe@example.com or call (555) 123-4567. My SSN is 123-45-6789 and my credit card is 4532 1234 5678 9012."
  }
}
----

[tabs]
====
Log::
+
--
When the action is set to *Log*, the policy logs detected PII with the actual values:

[source,text]
----
WARN Request: `Contact me at john.doe@example.com or call (555) 123-4567. My SSN is 123-45-6789 and my credit card is 4532 1234 5678 9012.` has sensitive data: [Email: john.doe@example.com, Phone: (555) 123-4567, SSN: 123-45-6789, CreditCard: 4532 1234 5678 9012]
----
--

Log and Mask::
+
--
When the action is set to *Log and mask*, the policy logs detected PII with masked values:

[source,text]
----
WARN Request: `Contact me at ********@example.com or call +1******567. My SSN is ***-**-6789 and my credit card is *************9012.` has sensitive data: [{"type": "Email", "masked_value": "********@example.com"}, {"type": "Phone", "masked_value": "+1******567"}, {"type": "SSN", "masked_value": "***-**-6789"}, {"type": "CreditCard", "masked_value": "*************9012"}]
----
--

Reject::
+
--
When the action is set to *Reject*, the policy blocks the request and returns an HTTP 403 error response. The agent does not receive the original request containing PII.

[source,json]
----
{
  "jsonrpc": "2.0",
  "id": null,
  "error": {
    "code": -32600,
    "message": "Request contains PII data: SSN: 123-45-6789",
    "data": [
      {
        "@type": "type.googleapis.com/google.rpc.ErrorInfo",
        "domain": "a2a-protocol.org",
        "reason": "FORBIDDEN",
        "metadata": { "detail": "Request contains PII data: SSN: 123-45-6789" }
      }
    ]
  }
}
----
--

=== Custom Pattern Example

This example shows detection of a custom AWS Access Key pattern in a request:

[source,json]
----
{
  "jsonrpc": "2.0",
  "method": "SendMessage",
  "params": {
    "message": {
      "parts": [
        {
          "text": "Use this AWS key: AKIAIOSFODNN7EXAMPLE for deployment"
        }
      ]
    }
  }
}
----

With a custom pattern configured (`name: AWS Access Key`, `pattern: AKIA[0-9A-Z]{16}`), the policy logs:

[source,json]
----
WARN Request: `Use this AWS key: AKIAIOSFODNN7EXAMPLE for deployment` has sensitive data: [AWS Access Key: AKIAIOSFODNN7EXAMPLE]
----

== Compliance and Data Flow

The following table shows where raw PII values may appear based on the configured action:

[%header,cols="1,2,2"]
|===
|Action
|Request Body on Wire
|Access Log

|Reject
|Blocked (HTTP 403 error with masked findings in error envelope)
|No log emitted on reject

|Log and mask
|Forwarded unchanged (raw PII flows upstream)
|Masked

|Log
|Forwarded unchanged (raw PII flows upstream)
|Raw
|===

IMPORTANT: For the A2A PII Detector policy, the *Log and mask* action only masks the access log, not the request body. Raw PII still flows to the upstream agent when using *Log* or *Log and mask* actions. Only *Reject* prevents PII from reaching the agent.

== Transport Support

The A2A PII Detector policy supports all three A2A v1 transports:

* *JSON-RPC over HTTP*: Returns HTTP 403 with JSON-RPC error envelope
* *HTTP+JSON*: Returns HTTP 403 with standard error structure
* *gRPC*: Returns HTTP 200 with grpc-status: 7 (PERMISSION_DENIED) in trailer
