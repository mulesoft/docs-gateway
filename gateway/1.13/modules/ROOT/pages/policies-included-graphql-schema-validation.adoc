== Summary

The GraphQL Schema Validation policy applies standard GraphQL validation rules, including field and argument correctness, fragments, directives, unions, interfaces, and other specification rules.

The policy loads the schema in these ways:

* If `source` is `context`, Flex Gateway pulls schema from your API asset in Exchange.
* If `source` is `inline`, you embed your schema directly in the policy configuration.

If the document includes an `@link` to the Apollo Federation specification URL, Flex Gateway uses this schema to validate all incoming requests.

After Flex Gateway extracts inline GraphQL operation text from the request, the policy runs validation. If Flex Gateway can't resolve normal operation text, such as persisted query flows, it skips these checks and logs a warning before it forwards the request to the upstream.

Although Flex Gateway loads the schema into memory, it logs a warning and forwards the request instead of validating it.

== Configuring Policy Parameters

include::partial$policy-title-headers.adoc[tag=configFile]

----
- policyRef:
    name: graphql-schema-validation-flex
  config:
    source: <string> // OPTIONAL, default: context; values: "context" or "inline"
    schema: <string> // REQUIRED when source is inline; omit when source is context
    blockOperation: <boolean> // OPTIONAL, default: true
----

[%header%autowidth.spread,cols="a,a,a,a"]
|===

| Parameter | Required | Default Value | Description

| `source`
| No
| `context`
| Where Flex Gateway retrieves the schema for validation. If set to `context`, Flex Gateway automatically loads the schema file from the API asset in Anypoint Exchange. If set to `inline` you provide the schema text directly in the policy configuration. This is the standard choice for local mode or environments that aren't connected to Exchange.

| `schema`
| Yes, when `source` is `inline`
| Omit for `context`
| The schema text used for validation. Required when `source` is set to `inline`.

| `blockOperation`
| No
| `true`
| How Flex Gateway handles requests that fail validation. If `true`, Flex Gateway blocks the request and returns a 400 Bad Request. If `false`, Flex Gateway logs a warning and forwards the request to your backend.

|===

==== Resource Configuration Example

This example validates against a minimal inline schema:

[source,yaml]
----
- policyRef:
    name: graphql-schema-validation-flex
  config:
    source: inline
    blockOperation: true
    schema: |
      type Query {
        hello: String
      }
----

include::partial$policy-title-headers.adoc[tag=ui]

[%header%autowidth.spread,cols="a,a,a,a"]
|===
s|Field s|Description s|Default Value s|Required 

| Block request 
| If enabled and the operation doesn't conform to the schema, Flex Gateway returns a 400 error. If disabled, Flex Gateway logs a warning and forwards the request. 
| Enabled 
| Yes
|===

[NOTE]
====
In connected mode, attach your schema (SDL) to the API asset in Exchange. Because Flex Gateway automatically retrieves the schema, configure only the Block request setting.

In local mode, because Flex Gateway can't fetch metadata from Exchange, set the schema source to inline and provide the schema text directly in your configuration.
====
