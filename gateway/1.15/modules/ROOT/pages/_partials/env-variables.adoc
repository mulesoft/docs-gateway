Omni Gateway provides these environment variables to configure your gateway:

[cols="3,2,4"]
|===
|Variable Name |Default Value |Description

|FLEX_CONNECTION_IDLE_TIMEOUT_SECONDS
|`60`
|Maximum number of seconds a connection can be idle before it times out. For more information, see xref:{page-mode}-timeout.adoc[].

|FLEX_STREAM_IDLE_TIMEOUT_SECONDS
|`300`
|Maximum number of seconds a stream can remain idle without receiving any data in either the inbound (client to Omni Gateway) or outbound (Omni Gateway to upstream service) direction. For more information, see xref:{page-mode}-timeout.adoc[].

|FLEX_UPSTREAM_CONNECTION_IDLE_TIMEOUT_SECONDS
|`60`
|Maximum number of seconds a stream between Omni Gateway and the upstream service can remain idle between requests. For more information, see xref:{page-mode}-timeout.adoc[].

|FLEX_UPSTREAM_RESPONSE_TIMEOUT_SECONDS
|`15`
|Maximum number of seconds an Omni Gateway waits for a response from an upstream service. For more information, see xref:{page-mode}-timeout.adoc[].

|FLEX_ENVOY_HEADERS_ENABLED
| `false`
|Allows (`true`) or removes (`false`) Envoy headers from requests. For more information, see xref:review-prerequisites.adoc[].

|FLEX_REWRITE_HOST_HEADER
|`true`
|Rewrite HTTP Host header to match upstream.

|FLEX_REMOVE_SERVER_HEADER
|`false`
|Removes the `Server` HTTP response header from outbound responses when set to `true`. Set to `true` to reduce exposure of server implementation details for security or compliance purposes.

|FLEX_HEADER_RAW_VALUE_ENABLE
|`tru`e
|Controls header encoding for external authorization. Set to `false` to send headers encoded in UTF-8. For more information, see xref:policies-included-external-authorization.adoc[].

|FLEX_FORWARD_CLIENT_CERT_DETAILS
|`SANITIZE`
|Controls how the `x-forwarded-client-cert` (XFCC) HTTP header is handled. Supported values are `SANITIZE`, `FORWARD_ONLY`, `APPEND_FORWARD`, `SANITIZE_SET`, and `ALWAYS_FORWARD_ONLY`. For more information, see https://www.envoyproxy.io/docs/envoy/latest/api-v3/extensions/filters/network/http_connection_manager/v3/http_connection_manager.proto#envoy-v3-api-enum-extensions-filters-network-http-connection-manager-v3-httpconnectionmanager-forwardclientcertdetails[HTTP connection manager (proto)] in the Envoy documentation.

|FLEX_DOWNSTREAM_CONNECTION_BUFFER_LIMIT_BYTES
|`1048576` (1 MB)
|Maximum size, in bytes, of read and write buffers for new connections. For more information, see xref:review-prerequisites.adoc[].

|FLEX_DATASOURCE_CONTROL_NODE_ENABLED
|`true`
|Enable configuration caching in Redis shared storage for Connected Mode replicas. This variable is enabled by default. To disable configuration caching, set this variable to `false`. For more information, see xref:conn-replica-caching.adoc[].

|FLEX_SERVICE_ENVOY_DRAIN_TIME
|`25`
|Drain period in seconds during shutdown before Omni Gateway exits gracefully. For more information, see xref:{page-mode}-monitor.adoc[].

|FLEX_SYNC_DEBOUNCE_TIME
|"5s"
|Specifies the amount of time to wait after detecting a configuration change before applying it. This prevents excessive reloading during rapid successive changes. The value must be a valid duration string, such as `"5s"` or `"500ms"`. For Kubernetes deployments, set this value with the `gateway.syncDebounceTime` Helm chart value. For more information, see <<set-env-variables>>.
ifeval::["{page-mode}" == "conn"]

|FLEX_STARTUP_DEBOUNCE_TIME
|`"30s"`
|Specifies the amount of time to wait for the initial batch of configuration from Anypoint Platform to settle before applying it when Omni Gateway starts. The value must be a valid duration string, such as `"30s"` or `"1m"`. For Kubernetes deployments, set this value with the `gateway.startupDebounceTime` Helm chart value. For more information, see <<set-env-variables>>.

In Omni Gateway versions earlier than 1.15, `FLEX_SYNC_DEBOUNCE_TIME` also controls the startup wait time.
endif::[]

|FLEX_DNS_REFRESH_RATE
|`5s`
|Sets how often Omni Gateway refreshes DNS for upstream service clusters. The value is a duration string that is clamped between `5s` and `60s`. Values below the minimum or above the maximum are adjusted to the nearest bound.

|FLEX_LOG_LEVEL
| `4` (INFO)
| Sets the logging level for Omni Gateway. For the environment variable configuration of log level, you specify a number that corresponds to the log level. Supported values are NONE:`-1`, FATAL:`0`, ERROR:`1`, WARN:`2`, INFO:`4`, DEBUG:`8`, and TRACE:`16`.

|FLEX_CONFIG
|N/A
|Provides Omni Gateway registration and configuration as a YAML-formatted string. The YAML content must be properly escaped to preserve special characters. Provide your registration and configuration as a string if deploying environments where file mounting isn't practical, such as Amazon ECS or Azure Container Apps.

|===

[[set-env-variables]]
== Set Environment Variables for Your Deployment Target

How you set an environment variable depends on where Omni Gateway runs. The examples in this section set the debounce time variables, but you can use the same approach for any variable in the previous table.

Omni Gateway reads environment variables only when it starts. After you set a variable, restart Omni Gateway to apply the change.

* <<set-env-variables-docker>>
* <<set-env-variables-linux>>
* <<set-env-variables-k8s>>

[[set-env-variables-docker]]
=== Set Environment Variables in a Docker Container

Pass each variable with the `-e` option in the `docker run` start command, for example:

[source,ssh]
----
docker run --rm \
-v "$(pwd)":/usr/local/share/mulesoft/flex-gateway/conf.d \
-p 8080:8080 \
-e FLEX_SYNC_DEBOUNCE_TIME=10s \
ifeval::["{page-mode}" == "conn"]
-e FLEX_STARTUP_DEBOUNCE_TIME=60s \
endif::[]
mulesoft/flex-gateway
----

Podman uses the same `-e` option in the `podman run` start command.

If you use Docker Compose, add the variables to the `environment` section of the service, for example:

[source,yaml]
----
services:
  flex-gateway:
    image: mulesoft/flex-gateway
    environment:
      FLEX_SYNC_DEBOUNCE_TIME: "10s"
ifeval::["{page-mode}" == "conn"]
      FLEX_STARTUP_DEBOUNCE_TIME: "60s"
endif::[]
----

[[set-env-variables-linux]]
=== Set Environment Variables for a Linux Service

When Omni Gateway runs as a Linux service, `systemd` sets its environment variables. Add the variables in a drop-in file for the `flex-gateway` service:

. Create a drop-in file named `env.conf` in the `/etc/systemd/system/flex-gateway.service.d/` directory:
+
[source,ssh]
----
sudo mkdir -p /etc/systemd/system/flex-gateway.service.d
sudo tee /etc/systemd/system/flex-gateway.service.d/env.conf > /dev/null <<'EOF'
[Service]
Environment=FLEX_SYNC_DEBOUNCE_TIME=10s
ifeval::["{page-mode}" == "conn"]
Environment=FLEX_STARTUP_DEBOUNCE_TIME=60s
endif::[]
EOF
----
+
Don't edit the `override.conf` file in the same directory. The Omni Gateway package installs and manages that file.

. Reload the `systemd` configuration and restart Omni Gateway:
+
[source,ssh]
----
sudo systemctl daemon-reload
sudo systemctl restart flex-gateway
----

. Verify that the service includes the new variables:
+
[source,ssh]
----
systemctl show flex-gateway --property=Environment
----

[[set-env-variables-k8s]]
=== Set Environment Variables in Kubernetes

When you deploy Omni Gateway with the Helm chart, the chart sets the environment variables on the Omni Gateway pod. Set the debounce times with these Helm chart values:

[cols="2,2"]
|===
|Helm Chart Value |Environment Variable

|`gateway.syncDebounceTime`
|`FLEX_SYNC_DEBOUNCE_TIME`

ifeval::["{page-mode}" == "conn"]
|`gateway.startupDebounceTime`
|`FLEX_STARTUP_DEBOUNCE_TIME`
endif::[]
|===

Don't use `extraEnvs` to set a variable that the chart already sets from a Helm chart value. Use the Helm chart value instead.

To change the values on an existing deployment, run `helm upgrade` with the `--set` option, for example:

[source,helm]
----
helm -n gateway upgrade ingress \
--wait \
--reuse-values \
flex-gateway/flex-gateway \
ifeval::["{page-mode}" == "conn"]
--set gateway.syncDebounceTime=10s \
--set gateway.startupDebounceTime=60s
endif::[]
ifeval::["{page-mode}" == "local"]
--set gateway.syncDebounceTime=10s
endif::[]
----

Alternatively, add the values to a configuration file that you pass with the `-f` option:

[source,yaml]
----
gateway:
  syncDebounceTime: "10s"
ifeval::["{page-mode}" == "conn"]
  startupDebounceTime: "60s"
endif::[]
----

To set a variable that doesn't have a Helm chart value, use `extraEnvs`, for example:

[source,yaml]
----
extraEnvs:
  - name: FLEX_REMOVE_SERVER_HEADER
    value: "true"
----

For more information about updating Helm chart values, see xref:gateway-k8-change-helm-settings.adoc[].
