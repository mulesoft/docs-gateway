//tag::intro[]
A default TLS context applies to every HTTPS API instance or upstream service that doesn't have its own TLS context, so you don't have to apply the same TLS context to each API instance and upstream service individually.

//end::intro[]

//tag::inbound-intro[]
* *Default inbound TLS* +
Applies to inbound requests on every HTTPS API instance that doesn't have an inbound TLS context.
//end::inbound-intro[]

//tag::outbound-intro[]
* *Default outbound TLS* +
Applies to every HTTPS upstream service that doesn't have an outbound TLS context, and to the outgoing requests that policies make. For example, the xref:policies-included-oauth-token-introspection.adoc[] sends token validation requests to an OAuth 2.0 service.
//end::outbound-intro[]

//tag::precedence[]

Omni Gateway applies default TLS contexts with the lowest priority:

* A TLS context that you apply to an API instance or upstream service always overrides the default TLS context.
* Default TLS contexts apply only to API instances and upstream services that use HTTPS. HTTP API instances and upstream services aren't affected.
* Omni Gateway implements inbound TLS at the port level. If any API instance on a port has an inbound TLS context, that context applies to the port instead of the default inbound TLS context.

//end::precedence[]

//tag::rm-byb[]
Before configuring a default TLS context, add a TLS context with the *Omni Gateway* target to a downloadable secret group. To add a TLS context, see <<add-a-tls-context, Add a TLS Context>>.

A default inbound TLS context requires a keystore. To require client certificates (inbound mTLS), select *Validate Client certificate* and add a truststore.

//end::rm-byb[]

//tag::rm-steps-start[]
. In Anypoint Platform, select *Runtime Manager*.
. Select *Omni Gateways*.
. Select your Omni Gateway.
. Open *Runtime Configurations*.
. Open *TLS*.
//end::rm-steps-start[]
//tag::rm-step-inbound[]
. To configure a default inbound TLS context, in *Default Inbound TLS*, select a *Secret Group* and a *TLS Context*.
//end::rm-step-inbound[]
//tag::rm-step-outbound[]
. To configure a default outbound TLS context, in *Default Outbound TLS*, select a *Secret Group* and a *TLS Context*.
//end::rm-step-outbound[]

. Click *Apply changes*.

To remove a default TLS context, clear its *Secret Group* and *TLS Context* fields, and then click *Apply changes*.

If Omni Gateway can't use the selected TLS context, for example, because the TLS context was deleted, Omni Gateway ignores that default TLS context, logs a warning, and applies the rest of the runtime configuration.

//end::rm-steps-end[]

//tag::local-config[]
Configure default TLS contexts in a `Configuration` resource:

[source,yaml]
----
apiVersion: gateway.mulesoft.com/v1alpha1
kind: Configuration
metadata:
  name: default-tls
spec:
  defaultTLS:
    inbound: # OPTIONAL
      certificate: # REQUIRED for inbound
        key: <string>
        crt: <string>
        keyPassphrase: <string> # OPTIONAL
      requireClientCertificate: <boolean> # OPTIONAL
      trustedCA: <string> # OPTIONAL
      alpn: <array> # OPTIONAL
      minVersion: <string> # OPTIONAL
      maxVersion: <string> # OPTIONAL
      ciphers: <array> # OPTIONAL
    outbound: # OPTIONAL
      skipValidation: <boolean> # OPTIONAL
      trustedCA: <string> # OPTIONAL
      certificate: # OPTIONAL
        key: <string>
        crt: <string>
        keyPassphrase: <string> # OPTIONAL
      alpn: <array> # OPTIONAL
      minVersion: <string> # OPTIONAL
      maxVersion: <string> # OPTIONAL
      ciphers: <array> # OPTIONAL
----

Add the file to the Omni Gateway configuration directory in the same way as the TLS context configuration files on this page.

Omni Gateway validates each default TLS context when you apply the `Configuration` resource. If a default TLS context is invalid, for example, because the certificate and key don't match or a cipher isn't supported, Omni Gateway rejects the resource and logs an error.

Not including optional parameters applies their default values.

*Default inbound TLS parameters:*

[%header%autowidth.spread,cols="a,a,a,a"]
|===
|Parameter | Required or Optional | Default Value | Description

| `certificate`
| Required
| N/A
| The server certificate that Omni Gateway presents to clients. To comply with security standards, all certificates must be 2048 bits or longer.

| `certificate.key`
| Required
| N/A
| The private key of the certificate, in PEM format.

| `certificate.crt`
| Required
| N/A
| The public certificate, in PEM format.

| `certificate.keyPassphrase`
| Optional, unless the private key is encrypted
| N/A
| The passphrase that decrypts the private key.

| `requireClientCertificate`
| Optional
| `false`
| If `true`, enables inbound mTLS. Clients must present a certificate signed by `trustedCA`.

| `trustedCA`
| Optional, unless `requireClientCertificate` is `true`
| N/A
| The CA that validates client certificates, in PEM format.

| `alpn`
| Optional
| `http/1.1` and `h2`
| A prioritized list of supported application-level protocols. Supported values are `http/1.1` and `h2`.

| `minVersion`
| Optional
| `1.2`
| The minimum TLS version allowed. Supported values are `1.2` and `1.3`.

| `maxVersion`
| Optional
| `1.3`
| The maximum TLS version allowed. Supported values are `1.2` and `1.3`.

| `ciphers`
| Optional
| `TLS_ECDHE_ECDSA_WITH_AES_128_GCM_SHA256`, `TLS_ECDHE_RSA_WITH_AES_128_GCM_SHA256`, `TLS_ECDHE_ECDSA_WITH_AES_256_GCM_SHA384`, `TLS_ECDHE_RSA_WITH_AES_256_GCM_SHA384`, `TLS_ECDHE_ECDSA_WITH_CHACHA20_POLY1305_SHA256`, `TLS_ECDHE_RSA_WITH_CHACHA20_POLY1305_SHA256`, and `TLS_ECDHE_PSK_WITH_CHACHA20_POLY1305_SHA256`
| A list of supported TLS 1.2 ciphers, in IANA format. For the supported ciphers, see <<local-support>>.
|===

*Default outbound TLS parameters:*

[%header%autowidth.spread,cols="a,a,a,a"]
|===
|Parameter | Required or Optional | Default Value | Description

| `skipValidation`
| Optional
| `false`
| If `true`, Omni Gateway doesn't validate upstream server certificates. Omni Gateway logs a warning while this setting is enabled.

| `trustedCA`
| Optional
| The operating system CAs
| The CA that validates upstream server certificates, in PEM format.

| `certificate`
| Optional
| N/A
| The client certificate that Omni Gateway presents for outbound mTLS. To comply with security standards, all certificates must be 2048 bits or longer.

| `certificate.key`
| Optional, unless `certificate` is set
| N/A
| The private key of the certificate, in PEM format.

| `certificate.crt`
| Optional, unless `certificate` is set
| N/A
| The public certificate, in PEM format.

| `certificate.keyPassphrase`
| Optional, unless the private key is encrypted
| N/A
| The passphrase that decrypts the private key.

| `alpn`
| Optional
| `http/1.1` and `h2`
| A prioritized list of supported application-level protocols. Supported values are `http/1.1` and `h2`.

| `minVersion`
| Optional
| `1.2`
| The minimum TLS version allowed. Supported values are `1.2` and `1.3`.

| `maxVersion`
| Optional
| `1.3`
| The maximum TLS version allowed. Supported values are `1.2` and `1.3`.

| `ciphers`
| Optional
| `TLS_ECDHE_ECDSA_WITH_AES_128_GCM_SHA256`, `TLS_ECDHE_RSA_WITH_AES_128_GCM_SHA256`, `TLS_ECDHE_ECDSA_WITH_AES_256_GCM_SHA384`, `TLS_ECDHE_RSA_WITH_AES_256_GCM_SHA384`, `TLS_ECDHE_ECDSA_WITH_CHACHA20_POLY1305_SHA256`, and `TLS_ECDHE_RSA_WITH_CHACHA20_POLY1305_SHA256`
| A list of supported TLS 1.2 ciphers, in IANA format. Ensure that your upstream services support the ciphers. For the supported ciphers, see <<local-support>>.
|===

*Sample configuration for a default inbound TLS context and a default outbound TLS context that validates upstream certificates with a private CA:*

[source,yaml]
----
apiVersion: gateway.mulesoft.com/v1alpha1
kind: Configuration
metadata:
  name: default-tls
spec:
  defaultTLS:
    inbound:
      certificate:
        key: |
          -----BEGIN PRIVATE KEY-----
          # insert private key
          -----END PRIVATE KEY-----
        crt: |
          -----BEGIN CERTIFICATE-----
          # insert certificate
          -----END CERTIFICATE-----
    outbound:
      trustedCA: |
        -----BEGIN CERTIFICATE-----
        # insert the CA that signs the upstream server certificates
        -----END CERTIFICATE-----
----

This example uses the default values for `alpn`, `minVersion`, `maxVersion`, and `ciphers`.

[NOTE]
====
The `defaultTLS.outboundPolicyCalls` parameter is deprecated. Use `defaultTLS.outbound` instead, which applies to both upstream services and outgoing policy requests. If you configure only `outboundPolicyCalls`, Omni Gateway applies it to outgoing policy requests only. If you configure both, Omni Gateway ignores `outboundPolicyCalls`. In both cases, Omni Gateway logs a warning.
====
