== Summary

The DataWeave Body Transformation Outbound policy transforms the body of outbound request or response traffic with a DataWeave script. Apply this policy to an upstream service to change the body of requests that Omni Gateway sends to the upstream service, or the body of responses that Omni Gateway receives from it.

Use this policy when you want to:

* Reshape a request body to match the format that an upstream service expects, so that clients don't need to change how they call the API.
* Reshape an upstream response body before it reaches the client, so that you can remove, rename, or combine fields.
* Convert a body between formats, such as JSON and XML, by declaring an output MIME type in the script.

To change headers instead of the body, use the xref:policies-outbound-dataweave-headers-transformation.adoc[DataWeave Headers Transformation Outbound] policy. To transform inbound traffic, use the xref:policies-included-dataweave-body-transformation.adoc[DataWeave Body Transformation] policy.

----
apiVersion: gateway.mulesoft.com/v1beta1
kind: PolicyBinding
metadata:
  name: dataweave-body-transformation-outbound
spec:
  targetRef:
    kind: Service
    name: upstream
  policyRef:
    name: dataweave-body-transformation-outbound-flex
  config:
    script: <string>        // REQUIRED - DataWeave script
    requestFlow: <string>   // REQUIRED - "onRequest" or "onResponse"
----

== How This Policy Works

The policy transforms the body of the traffic on the side that Request flow (`requestFlow`) sets. Set it to *On request* (`onRequest`) to transform the request that Omni Gateway sends to the upstream service. Set it to *On response* (`onResponse`) to transform the response that Omni Gateway receives from the upstream service. The other side passes through unchanged.

The script receives the request or response headers in `attributes.headers` and the body in `payload`, and the value that the script returns becomes the new body. If the script declares an output MIME type, such as `output application/json`, Omni Gateway uses it as the `Content-Type` of the transformed body. Otherwise, Omni Gateway keeps the original `Content-Type`.

[[payload-handling]]
=== Payload Handling

The policy buffers the full body on the configured side, runs the script, and then updates the `Content-Length` header. Server-sent event (SSE) bodies, which have the `text/event-stream` content type, aren't buffered. The policy transforms SSE bodies one event at a time and removes the `Content-Length` header instead of updating it.

== Example Configurations

The following examples demonstrate common configuration patterns for the DataWeave Body Transformation Outbound policy.

=== Transform the Request Body

This example transforms the request body that Omni Gateway sends to the upstream service. The new body includes the value of the `custom-client-header` header and fields from the original payload:

[source,yaml]
----
apiVersion: gateway.mulesoft.com/v1beta1
kind: PolicyBinding
metadata:
  name: dataweave-body-transformation-outbound
spec:
  targetRef:
    kind: Service
    name: upstream
  policyRef:
    name: dataweave-body-transformation-outbound-flex
  config:
    requestFlow: onRequest
    script: |
      {
        "id": attributes.headers.'custom-client-header',
        "username": payload.name ++ payload.surname
      }
----

=== Transform the Response Body and Set the Output Format

This example transforms the response body from the upstream service and sets the output format to XML:

[source,yaml]
----
apiVersion: gateway.mulesoft.com/v1beta1
kind: PolicyBinding
metadata:
  name: dataweave-body-transformation-outbound
spec:
  targetRef:
    kind: Service
    name: upstream
  policyRef:
    name: dataweave-body-transformation-outbound-flex
  config:
    requestFlow: onResponse
    script: |
      output application/xml
      ---
      {
        "trace": attributes.headers.'X-Amzn-Trace-Id',
        "custom-data": "custom-value"
      }
----
