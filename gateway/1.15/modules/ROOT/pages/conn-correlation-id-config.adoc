* xref:conn-correlation-id-config.adoc#runtime-manager-config[Runtime Manager runtime configurations]: Applies to all API instances in the gateway.

[[runtime-manager-config]]
== Configure in Runtime Manager

. In Anypoint Platform, select *Runtime Manager*.
. Select *Omni Gateways*.
. Select your Omni Gateway.
. Open *Runtime configuration*.
. Open the *Tracing* tab.
// TODO: Confirm the Omni Gateways menu name (the page header reads "Self-Managed Omni Gateways").
. Turn on *Enable Tracing*.
+
Runtime Manager requires tracing to be enabled to apply a correlation ID.
. Turn on *Enable Correlation ID*.
. In *Header*, enter the name of the header that carries the correlation ID.
. In *Generation Expression*, enter the expression that generates the correlation ID when the request doesn't include the header. For example, `prefix(uuid(), 'REQ-')`.
+
In Runtime Manager, *Header* and *Generation Expression* are both required.
. Click *Apply changes*.

[[yaml-resource-config]]
== Configure with a YAML Resource

Add `correlationId` under `spec.tracing` of a Configuration resource, and then apply the resource:

[source,yaml]
----
apiVersion: gateway.mulesoft.com/v1beta1
kind: Configuration
metadata:
  name: correlation-id
spec:
  tracing:
    correlationId:
      header: X-Correlation-Id
      generationExpression: "prefix(uuid(), 'REQ-')"
----

Omni Gateway applies changes without restarting. To disable the correlation ID, remove `correlationId` from the resource.

[[policy-config]]
== Override the Correlation ID for an API Instance

To use a different header or generation expression for one API instance, apply the xref:policies-included-correlation-id-override.adoc[] policy to the API instance. The policy replaces the correlation ID configuration of the gateway for that API instance. Other API instances keep the configuration of the gateway.
