You can configure these timeouts for Managed Omni Gateway via:

* Managed Omni Gateway deployment: Set initial timeout values when you create the gateway.
* Runtime Manager runtime configurations: Applies to all API instances in the gateway after the gateway is deployed.
* Policy: Applies to one API instance or upstream and provides granular control.

== Timeouts for Managed Omni Gateway on Runtime Fabric on OpenShift

On Runtime Fabric on Red Hat OpenShift, the OpenShift route in front of Managed Omni Gateway has its own timeout. Requests can time out at either layer.

[%header%autowidth.spread,cols="a,a,a,a,a"]
|===
| Layer | Timeout | Default | Where to Configure | Result When Exceeded

| OpenShift route
| Route timeout
| 30 seconds
| `haproxy.router.openshift.io/timeout` annotation on the route
| `504 Gateway Timeout`

| Managed Omni Gateway
| Response timeout
| 15 seconds
| See <<configure-timeouts-during-managed-gateway-deployment,Configure Timeouts During Managed Gateway Deployment>>
| `504 Gateway Timeout`

| Managed Omni Gateway
| Upstream idle timeout
| 60 seconds
| See <<configure-timeouts-during-managed-gateway-deployment,Configure Timeouts During Managed Gateway Deployment>>
| Connection reset

| Managed Omni Gateway
| Stream idle timeout
| 300 seconds
| See <<configure-timeouts-during-managed-gateway-deployment,Configure Timeouts During Managed Gateway Deployment>>
| Connection reset
|===

If you increase the response timeout above the route timeout, the route returns `504 Gateway Timeout` before Managed Omni Gateway receives the upstream response. Set the route timeout higher than the longest Managed Omni Gateway timeout that applies to requests through the route.

On Runtime Fabric, the agent creates the route from a route template. Add the `haproxy.router.openshift.io/timeout` annotation to the template, not to the route. See xref:runtime-fabric::configure-openshift-routes.adoc[].
