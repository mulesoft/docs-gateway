== Summary

The Injection Protection policy scans incoming request headers, path, query string, and body for SQL injection, XSS (Cross-Site Scripting), and custom injection attacks. Enable built-in SQL and XSS by adding `"sql"` and/or `"xss"` to `builtInProtections`. Add custom protections by defining rules in `customProtections` (each rule has a name and a regex pattern). Choose which parts of the request to scan (path and query, headers, body) and whether to reject matching requests or allow them and log a warning.

The policy checks the chosen areas against the enabled built-in and custom rules. When a rule matches and `rejectRequests` is `true`, the gateway returns `400` (Bad Request) and adds the response header `x-injection-protection: blocked`. When `rejectRequests` is `false`, the gateway allows the request and logs a warning.

== Configuring Policy Parameters

include::partial$policy-title-headers.adoc[tag=configFile]

----
- policyRef:
    name: injection-protection-flex
  config:
    builtInProtections: ["sql", "xss"]  // REQUIRED: include "sql", "xss", or both
    customProtections: []               // OPTIONAL: list of { name: <string>, regex: <string> }
    protectPathAndQuery: <bool>         // REQUIRED
    protectHeaders: <bool>              // REQUIRED
    protectBody: <bool>                 // REQUIRED
    headersToProtect: <string>          // OPTIONAL, default: "" (empty = all headers)
    rejectRequests: <bool>              // REQUIRED: true = reject with 400, false = allow and log
----

Set at least one of `protectPathAndQuery`, `protectHeaders`, or `protectBody` to `true`. Configure at least one protection: include one or both of `"sql"` and `"xss"` in `builtInProtections`, or add one or more entries in `customProtections` (or both).

[%header%autowidth.spread,cols="a,a,a,a"]
|===
|Parameter | Required | Default Value | Description

| `builtInProtections`
| Yes (at least one protection required)
| —
| Built-in protection types: SQL and XSS. Add `"sql"` and/or `"xss"` to enable one or both. SQL patterns include tautologies (`OR 1=1`), comment-based injection (`--`, `#`), union/select, and `DROP/INSERT/UPDATE/DELETE`. XSS patterns include script/iframe tags, event handlers, and common script schemes.

| `customProtections`
| No
| []
| Add custom protection rules. Each rule has a `name` and a `regex` pattern. Use for application-specific or other injection types. Names and regex must be non-empty and valid.

| `protectPathAndQuery`
| Yes
| —
| When `true`, the policy checks the request path and query string. The policy URL-decodes the path and query before matching.

| `protectHeaders`
| Yes
| —
| When `true`, the policy checks request headers. `headersToProtect` specifies which headers the policy checks.

| `headersToProtect`
| No
| "" (empty)
| Comma-separated list of header names to check (case-insensitive). Empty string means the policy checks all headers. Not used when `protectHeaders` is `false`.

| `protectBody`
| Yes
| —
| When `true`, the policy checks the request body for injection patterns.

| `rejectRequests`
| Yes
| —
| When `true`, the gateway rejects matching requests with `400` and a JSON error message. When `false`, the gateway allows matching requests and logs a warning.

|===

==== Resource Configuration Example

----
- policyRef:
    name: injection-protection-flex
  config:
    builtInProtections: ["sql", "xss"]
    customProtections: []
    protectPathAndQuery: true
    protectHeaders: true
    headersToProtect: "referer,user-agent"
    protectBody: true
    rejectRequests: true
----
