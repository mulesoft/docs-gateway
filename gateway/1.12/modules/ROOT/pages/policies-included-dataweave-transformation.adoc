== Summary

The DataWeave Transformation policy modifies or validates HTTP messages with DataWeave scripts. It uses three distinct policy variants. Apply one or more to an API as needed:

Header transformation:: Transforms request or response headers with a DataWeave script. The script receives headers and the message body, and it returns a `map` of header names to values. In the request or response, the gateway removes existing headers and runs the script with header bindings. The script output is a `map`. Each entry becomes a header. For multi-value headers, use a list of values.
Body transformation:: Transforms request or response body content with a DataWeave script. The script receives headers and the body, and it streams the transformed output. In the request or response, the gateway processes the body in streaming mode and automatically updates `Content-Type` and `Content-Length`.
Script evaluation:: Evaluates a DataWeave script on the request or response headers and body to allow or block the message. The script returns an object with a Boolean `success` value. If `success` is `false`, the object includes a `response` with `statusCode`, `body`, and `headers`. In the request or response phase as set by `requestFlow`, the gateway runs the script. If `success` is `false`, the gateway stops processing and returns the response defined in the `response` object. If `success` is `true`, the message continues.

If a script execution error occurs, such as an invalid output format or runtime error, the gateway returns a `400` error code and terminates the request or response.

== Configure Header Transformation Policy Parameters

The DataWeave script returns a `map` where keys are header names and values are header values. For multi-value headers, use a list of values. Apply the transformation to the request or the response. Optionally, the script receives the message body.

In Local Mode, apply the policy via declarative configuration using the `request-header-transformation` policy. In Managed Flex Gateway and Flex Gateway Connected mode, apply the policy from the UI and select the header transformation type.

include::partial$policy-title-headers.adoc[tag=configFileTitleOnly]

----
- policyRef:
    name: request-header-transformation
  config:
    script: <string>        // REQUIRED - DataWeave script
    requestFlow: <string>   // REQUIRED - "onRequest" or "onResponse"
    requiresPayload: <boolean>  // OPTIONAL, default: false
----

[%header%autowidth.spread,cols="a,a,a,a"]
|===
|Parameter | Required or Optional | Default Value | Description

| `script`
| Required
| —
| A DataWeave script that returns a `map` of header names to values. The script receives `attributes.headers`. If `requiresPayload` is true, it also receives the message body in the `payload` binding.

| `requestFlow`
| Required
| —
| The phase when the policy runs: `onRequest` for request headers and body, or `onResponse` for response headers and body.

| `requiresPayload`
| Optional
| false
| If true, the script receives the message body in the `payload` binding. The gateway buffers the body for the transformation.
|===

==== Header Transformation Resource Configuration Example

----
- policyRef:
    name: request-header-transformation
  config:
    script: |
      %dw 2.0
      output application/java
      ---
      {
        "X-Request-Id": attributes.headers["x-request-id"] default uuid(),
        "X-Forwarded-Host": attributes.headers["host"]
      }
    requestFlow: "onRequest"
    requiresPayload: false
----

== Configure Body Transformation Policy Parameters

The DataWeave script receives `attributes.headers` and `payload`. The gateway streams body processing. If the script declares an output MIME type, such as `output application/json`, the gateway uses it for the transformed response. Otherwise, the gateway keeps the original `Content-Type`.

In Local Mode, apply the policy via declarative configuration using the `request-body-transformation` policy. In Managed Flex Gateway and Flex Gateway Connected mode, apply the policy from the UI and select the body transformation type.

include::partial$policy-title-headers.adoc[tag=configFileTitleOnly]

----
- policyRef:
    name: request-body-transformation
  config:
    script: <string>        // REQUIRED - DataWeave script
    requestFlow: <string>   // REQUIRED - "onRequest" or "onResponse"
----

[%header%autowidth.spread,cols="a,a,a,a"]
|===
|Parameter | Required or Optional | Default Value | Description

| `script`
| Required
| —
| A DataWeave script that transforms the body. The script receives `attributes.headers` and the `payload`. If needed, declare the output MIME type in the script, such as `output application/json`.

| `requestFlow`
| Required
| —
| The phase when the policy runs: `onRequest` for the request body, or `onResponse` for the response body.
|===


=== Body Transformation Resource Configuration Example

----
- policyRef:
    name: request-body-transformation
  config:
    script: |
      %dw 2.0
      output application/json
      ---
      payload mapObject (value, key) -> { (key): value }
    requestFlow: "onRequest"
----

== Configure Script Evaluation Policy Parameters

The gateway evaluates a DataWeave script to allow or block the message. The script accesses headers and the body. It returns an object with a Boolean `success` value. If `success` is `false`, the script returns a `response` object with `statusCode`, `body`, and `headers`. The gateway sends that status code, body, and headers to the client as the immediate HTTP response.

Result format: 

* Success: `{ "success": true }`
* Error: `{ "success": false, "response": { "body": "...", "headers": {}, "statusCode": 400 } }`

In Local Mode, apply the policy via declarative configuration using the `script-evaluation-transformation` policy. In Managed Flex Gateway and Flex Gateway Connected mode, apply the policy from the UI and select the script evaluation type.

include::partial$policy-title-headers.adoc[tag=configFileTitleOnly]

----
- policyRef:
    name: script-evaluation-transformation
  config:
    script: <string>        // REQUIRED - DataWeave script
    requestFlow: <string>   // REQUIRED - "onRequest" or "onResponse"
    requiresPayload: <boolean>  // OPTIONAL, default: false
----

[%header%autowidth.spread,cols="a,a,a,a"]
|===
|Parameter | Required or Optional | Default Value | Description

| `script`
| Required
| —
| A DataWeave script that returns an object with a Boolean `success` field. If `success` is `false`, the optional `response` is: `{ "body": string, "headers": object, "statusCode": number }`.

| `requestFlow`
| Required
| —
| The phase when the policy runs: `onRequest` or `onResponse`.

| `requiresPayload`
| Optional
| false
| If true, the script receives the message body in the `payload` binding. If true and the body is missing, the gateway returns an error.
|===

=== Script Evaluation Resource Configuration Example

----
- policyRef:
    name: script-evaluation-transformation
  config:
    script: |
      %dw 2.0
      output application/java
      ---
      if (attributes.headers["x-api-key"] != null) { success: true }
      else { success: false, response: { statusCode: 401, body: "Missing API key", headers: {} } }
    requestFlow: "onRequest"
    requiresPayload: false
----

|===
| Parameter | Description
| Policy type | The type of policy to apply. Options are header transformation, body transformation, or script evaluation.
| Script | The DataWeave script for the selected policy type.
| Request flow | The flow where the policy applies. Options are request or response.
