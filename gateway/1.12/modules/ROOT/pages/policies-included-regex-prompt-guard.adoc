== Summary

The Regex Prompt Guard policy scans LLM prompts and blocks requests when prompt content matches configured deny-listed regex patterns.

This policy helps protect LLM-powered APIs from text-based attacks, such as prompt injection, jailbreak attempts, SQL injection patterns, and HTML or script injection.

The policy evaluates requests for supported OpenAI-compatible payload formats and returns a `403` response when a configured pattern is matched.

| Element | Required | Description
| Deny Patterns | Yes | List of regex patterns to block. Each item contains a pattern name and regex expression.
| Pattern Name | Yes | Human-readable pattern name. The policy includes this value in the blocked-response details.
| Regex Pattern | Yes | PCRE-compatible regex expression used to match prompt content. Use `(?i)` for case-insensitive matching.
|===

== How This Policy Works

For incoming requests, the policy:

. Processes `POST` requests with JSON content.
. Detects supported LLM request formats by using the `x-input-format` header and payload structure.
. Extracts prompt text from supported OpenAI request bodies.
. Compares extracted prompt content against each configured deny pattern.
. Blocks the request with `403 Forbidden` if any pattern matches.

The policy supports OpenAI Chat Completions and OpenAI Responses API request formats.

=== Response on Block

When a request is blocked, the policy returns a response body similar to:

[source,json]
----
{
  "error": "Request blocked - content matches denied pattern",
  "matched_patterns": [
    "prompt-injection"
  ]
}
----
