== Summary

The OAuth 2.0 On-Behalf-Of (OBO) Credential Injection policy exchanges an incoming bearer token for a new token targeting an upstream service using OAuth 2.0 Token Exchange (RFC 8693). This policy is applied to outbound traffic (gateway → backend) and automatically handles OAuth 2.0 token exchange for backend services. It extracts the bearer token from incoming requests, exchanges it with an identity provider using RFC 8693 Token Exchange, and injects the new token into the Authorization header before forwarding to the backend.

==== Configuration Example

----
- policyRef:
    name: credential-injection-oauth2-obo-policy-flex
  config:
    clientId: my-gateway-client
    clientSecret: client-secret
    tokenEndpoint: https://keycloak.example.com/auth/realms/myrealm/protocol/openid-connect/token
    targetType: audience
    targetValue: backend-api
    scope: read write
    timeout: 10000
----

==== Target Type Configuration

The `targetType` parameter determines which RFC 8693 parameter is used in the token exchange request:

* **`audience`** (default): Uses the `audience` parameter - logical name of the target service
* **`resource`**: Uses the `resource` parameter (RFC 8707) - physical URI of the target resource

==== How It Works

1. **Extract Token**: The policy extracts the Bearer token from the incoming request's Authorization header
2. **Token Exchange**: Sends RFC 8693 compliant request to the token endpoint:
   * `grant_type`: `urn:ietf:params:oauth:grant-type:token-exchange`
   * `subject_token`: The extracted bearer token
   * `subject_token_type`: `urn:ietf:params:oauth:token-type:access_token`
   * `audience` or `resource`: Based on `targetType` configuration
   * `scope`: If configured
3. **Inject Token**: Replaces the Authorization header with the new token
4. **Forward Request**: Continues to the backend with the exchanged token

==== Error Handling

The policy returns the following error codes:

|===
|Status Code | Error | Description

| 401
| `missing_authorization`
| No Authorization header in request

| 401
| `invalid_authorization_format`
| Authorization header is not Bearer format

| 502
| `token_exchange_failed`
| Token endpoint error or unreachable after retries
|===

All errors are logged with detailed context for debugging.
