LLM Proxy provides a unified access layer for multiple Large Language Model (LLM) providers. LLM Proxy are deployed to Flex Gateway to enable governance, intelligent routing, and cost management for AI applications.

By creating a proxy, the user defines a singular LLM service that can receive requests for multiple providers, such as Open AI or Gemini. This simplifies the developer experience. You can add new models to the service seamlessly without changing the endpoint.

image::llm-proxy.png["An LLM Proxy with a single endpoint routing requests to multiple LLM providers"]

Depending on configuration, the proxy then sends the request to the model defined by the user or dynamically sends the request to the provider that best matches the request. 

* <<model-based-routing>>: Static routing. The user specifies what model the LLM Proxy should send the request to.
* <<semantic-routing>>: Dynamic routing. The LLM Proxy chooses which model to send the request to based on the request content.

[[create-an-llm-proxy]]
== Create an LLM Proxy

. From API Manager, click *LLM Proxies*.
. Click *Add LLM Proxy*.
. Configure the *Inbound Endpoint* of the LLM Proxy:
.. Create a new LLM Proxy or choose an existing LLM Proxy from Exchange.
.. Define a *LLM Proxy Name*.
.. Select an endpoint *Format*.
+
NOTE: Only Open AI format is supported for Limited Availability GA.
.. Define a *Base path*.
.. Select *Advanced options* if necessary.
.. Click *Next*.
. Select a Flex Gateway to deploy the server instance to from *Select a gateway*.
. Configure the routes that comprise the *Outbound Endpoint*:
.. Select your *LLM Provider*.
.. Ensure the *URL* for your provider is correct. Edit if necessary.
.. Enter your *Key* for your LLM Provider.
.. Select a *Target Model* to override the model specified in the payload.
.. Click *Add LLM Route* to add additional routes. Complete the previous steps to configure the new route.
. If adding multiple routes, select a *Routing strategy*. To configure your routing strategy, see:
.. <<configure-model-based-routing>>
.. <<configure-semantic-routing>>
. 
. Click Save & Deploy.

== Model-Based Routing

Model-based routing is static routing. In the request, the user specifies what model the LLM Proxy should send the request to. To ensure users 

By specifying a target model, LLM Proxy can override the model version provided by the user.

[[configure-model-based-routing]]
=== Configure Model-Based Routing

. Configure multiple routes. Click *Add LLM Route* to create new routes.
. Select *Model-based* for *Routing strategy*.
. Choose to enable a *Fallback route*. If enabling a fallback route:
.. Select a *Route* to fallback to.
.. Select a target model for the fallback route to use.
. If no fall back route is configured and a route fails, a error response is returned.
. Return to <<create-an-llm-proxy>> step 7 to finish configuring your LLM Proxy.

[[model-based-routing-example-request]]
=== Model-Based Routing Example Request

This is an example request to the LLM Proxy using model-based routing. The request is sent to the Open AI GPT-5 nano model:

----
curl --location --request POST 'https://llm-proxy-gateway-iiexmc.vmizg1.usa-e1.qax.cloudhub.io/chat/completions' \
--header 'Content-Type: application/json' \
--header 'client_id: 30813d6014e84838b1b01b5144400021' \
--header 'client_secret: C1F2dCE8aA234581B121d736d7E1c41e' \
--data-raw '{
    "model": "openai/gpt-5-nano",
    "input": "What is Artificial Intelligence"
}'
----

[[semantic-routing]]
== Semantic Routing

Semantic routing is dynamic routing where the LLM Proxy chooses which model to send the request to. For Sematic Routing, the user creates prompt topics for each route. When a request is sent to the LLM Proxy, a semantic service compares the request to the define topic utterances and sends the request to the route that best matches it.

=== Define a Semantic Service

A semantic service compares the request to the define topic utterances and sends the request to the route that best matches it. To define a semantic service:

. From API Manager, click *Semantic Service Setup*.
. Click *+ Create Semantic Service*.
. Select a *Embedding Service Provider*.
. Select a *Model*.
. Select the desired *Salesforce org*.
. Enter the *Client ID* and *Client Secret* for your Salesforce org. 
. Click *Deploy*.

To edit a semantic service:

. From *Semantic Service Setup*, click the three-dots menu (image:three-dots-menu.png[5%,5%]) of the semantic service you want to edit.
. Make the necessary edits.
. Click *Redeploy*.

[[configure-semantic-routing]]
=== Configure Semantic Routing

. Configure multiple routes. Click *Add LLM Route* to create new routes.
. Select *Semantic* for *Routing strategy*.
. Select a *Target Model* for each route.
. Define a prompt topics for the routes:
.. Click the *Select prompt topics*.
.. Click *+ Create prompt topic*.
.. Define a *Prompt topic name*.
.. Define a *Prompt utterances* or click *Upload utterances* to upload a plain text file containing your prompt utterances.
.. Click *Create*.
.. Create multiple prompt topics for each route as needed.
. Configure a *Fallback route*:
.. Specify an accuracy threshold. When the accuracy of the semantic match is less than this threshold, traffic is sent to the fallback route.
.. Select a *Route* to fallback to.
.. Select a *Target model* for the fallback route to use.
. Create a *Semantic prompt guard* to block users from asking the server about specific topics:
.. Click *+ Create deny list*.
.. Define a *Prompt topic name*.
.. Define a *Prompt utterances* or click *Upload utterances* to upload a plain text file containing your prompt utterances.
.. Click *Create*.
.. Create multiple deny list topics to better protect your LLM Proxy.
+
NOTE: Creating a semantic prompt guard automatically applies the Semantic Prompt Guard policy.
. Return to <<create-an-llm-proxy>> step 7 to finish configuring your LLM Proxy.

[[semantic-routing-example-request]]
=== Semantic Routing Example Request

This is an example request to the LLM Proxy using semantic routing. No model is specified in the request. If a model is specified, it is ignored:

----
curl --location 'https://llm-proxy-gateway-1-11-5-iiexmc.vmizg1.usa-e1.qax.cloudhub.io/llm-proxy-semantic/chat/completions' \
--header 'Content-Type: application/json' \
--header 'client_id: <YOUR_CLIENT_ID>' \
--header 'client_secret: <YOUR_CLIENT_SECRET>' \
--data '{
  "messages": [
    {
      "role": "user",
      "content": "Provide a step-by-step guide for authenticating an API request."
    }
  ]
}'
----
