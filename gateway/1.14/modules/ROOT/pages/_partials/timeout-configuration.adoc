//tag::timeout-types[]
Omni Gateway offers these timeouts to improve service quality and reduce computing resource waste:

* *Stream Idle Timeout* +
The Stream Idle Timeout enables you to set a maximum amount of a time a stream can remain idle without receiving any data in either the inbound (client to Omni Gateway) or outbound (Omni Gateway to upstream service) direction.
+
By default, all Omni Gateway API instances have a stream timeout of 300 seconds.

* *Upstream Idle Timeout* +
The Upstream Idle Timeout enables you to set a maximum amount of time a stream between Omni Gateway and the upstream service can remain idle between requests.
+
By default, all Omni Gateway API instances have an upstream idle timeout of 60 seconds.

* *Response Timeout* +
The Response Timeout enables you to set a maximum amount of a time Omni Gateway waits for a response from an upstream service. The timeout time starts at the last request sent by Omni Gateway.
+
By default, all Omni Gateway API instances have a response timeout of 15 seconds.
//end::timeout-types[]

//tag::timeout-runtime-manager[]
== Configure Timeouts in Runtime Manager

. In Anypoint Platform, select *Runtime Manager*.
. Select *Omni Gateways*.
. Select your Omni Gateway.
. Open *Runtime Configurations*.
. Open *Timeouts*.
. Set values for *Stream Idle Timeout*, *Upstream Connection Idle Timeout*, and *Upstream Response Timeout*.
. Apply the changes.

//end::timeout-runtime-manager[]

//tag::timeout-configuration-env-var[]
== Configure Timeouts via Environment Variables

Configure timeouts with these environment variables:

----
FLEX_STREAM_IDLE_TIMEOUT_SECONDS: 300
FLEX_UPSTREAM_CONNECTION_IDLE_TIMEOUT_SECONDS/FLEX_CONNECTION_IDLE_TIMEOUT_SECONDS: 60
FLEX_UPSTREAM_RESPONSE_TIMEOUT_SECONDS: 15
----

Edit the variables with your desired configurations.

//end::timeout-configuration-env-var[]

//tag::timeout-configuration-yaml[]
== Configure Timeouts via YAML Configuration Resources

Edit and then apply this configuration resource to update your timeouts:

[source,yaml]
----
apiVersion: gateway.mulesoft.com/v1alpha1
kind: Configuration
metadata:
  name: timeouts-config
spec:
  timeouts:
    upstreamConnectionIdleSeconds: 60
    upstreamResponseSeconds: 15
    streamIdleSeconds: 300
----

//end::timeout-configuration-yaml[]

//tag::timeout-precedence[]
[[timeout-precedence]]
== Timeout Precedence

Omni Gateway determines the effective value of each timeout for an API instance in this order of precedence. The first value that is set for that timeout takes precedence:

//end::timeout-precedence[]

//tag::timeout-precedence-managed[]
. *Policy*: A Response Timeout or Stream Idle Timeout policy applied to the API instance.
. *Runtime Manager runtime configuration*: The value set in *Runtime Configurations > Timeouts*.
. *Built-in default*: Used if neither of the other values is set. For example, the default Upstream Response Timeout is 15 seconds.
//end::timeout-precedence-managed[]

//tag::timeout-precedence-conn[]
. *Policy*: A Response Timeout or Stream Idle Timeout policy applied to the API instance.
. *Runtime Manager runtime configuration or Configuration resource*: Used if set for that timeout.
. *Environment variable*: Used if no Runtime Manager or Configuration resource value is set for that timeout.
. *Built-in default*: Used if none of the other values is set. For example, the default Upstream Response Timeout is 15 seconds.
//end::timeout-precedence-conn[]

//tag::timeout-precedence-details[]
A policy value overrides the gateway-level value for the API instance it's applied to, whether the policy value is higher or lower than the gateway-level value. API instances without the policy use the gateway-level value. The lowest value doesn't take precedence.

For example, this table shows the effective response timeout for an upstream service that takes 35 seconds to respond:

[%header%autowidth.spread,cols="a,a,a,a"]
|===
| Gateway-Level Upstream Response Timeout | Response Timeout Policy | Effective Timeout | Result
| 30 seconds | 40 seconds | 40 seconds | The request succeeds.
| 40 seconds | 30 seconds | 30 seconds | Omni Gateway returns `504` after 30 seconds.
| 30 seconds | Not applied | 30 seconds | Omni Gateway returns `504` after 30 seconds.
|===

//end::timeout-precedence-details[]

//tag::timeout-precedence-conn-sync[]
Runtime Manager runtime configurations and environment variables don't synchronize. Changing a timeout in Runtime Manager doesn't update the corresponding `FLEX_*` environment variable on the gateway. Because the Runtime Manager value takes precedence, the environment variable has no effect on that timeout while the Runtime Manager value is set.

//end::timeout-precedence-conn-sync[]
